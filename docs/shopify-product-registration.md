# Shopify 商品登録マニュアル

C AND+S サイト向けの商品登録手順です。Shopify管理画面を初めて使う人でも、この順で作業すれば登録できます。

技術的なフィールド定義は [shopify-content-model.md](./shopify-content-model.md) を参照してください。

---

## このマニュアルでできること

Shopifyに商品を登録すると、サイトの次の場所に反映されます。

- 商品一覧：`/products`
- 商品詳細：`/products/（URLハンドル）`

同じURLハンドルの商品がサイト側にすでに存在する場合、**Shopifyの内容が優先**されます。未完成のまま公開すると、一覧・詳細が途中の内容に切り替わるので注意してください。

---

## 最初に知っておくこと

### 自動で入る項目

| 項目 | 内容 |
| --- | --- |
| Member only | 商品を**保存したあと**、Shopify Flow が `False`（一般販売）を自動設定します |
| SALE表示 | 比較価格（通常価格）が販売価格より高いと、サイト側で自動表示します |
| カテゴリ表示 | 商品の `Category` を選ぶと、一覧の分類・商品カード・詳細ページのパンクズが同じ文言とリンクになります |

「商品を追加」画面を開いただけでは Flow は動きません。**初めて保存したあと**に `Member only` が入ります。数秒待って画面を再読み込みしてください。

### 自分で入力する項目

タイトル、説明、URLハンドル、**Category**、公開設定、バリエーション、価格、画像・動画、Feature、Size & Spec、販売ステータス、NEW表示 など。

### 公開の考え方

| 状態 | サイトでの見え方 |
| --- | --- |
| 下書き / Headless未公開 | サイトには出ません |
| アクティブ + Headless公開 | サイトに出ます（内容が途中でも出ます） |

テスト中でサイトに出したくない場合は、Headless の公開を外してください。

## 登録の全体の流れ

1. 商品を作成して保存する
2. Category を選ぶ
3. URLハンドルを半角英数字にする
4. 公開設定を確認する
5. バリエーション（カラー）を登録する
6. 画像・動画をアップロードしてギャラリーへ紐付ける
7. 商品の表示設定（会員限定 / NEW / 販売ステータス）を入れる
8. Feature を登録する
9. Size & Spec を登録する
10. 関連商品がある場合のみ紐付ける
11. サイトで確認する

MOYA500 は完成例です。NOKUTA はタイトル・説明・ハンドルまで入っている途中状態です。

---

## 手順1. 商品を作成する

1. Shopify管理画面左メニューの「商品管理」を開く
2. 「商品を追加」をクリック
3. 次を入力する
   - タイトル：サイトに出す商品名（例：`NOKUTA`）
   - 説明：商品詳細ページの説明文
   - Category：メタフィールドからカテゴリを**選択**する（手順1の後半）
4. 右上の「保存」をクリックする

Shopify標準の「商品タイプ」は自由入力のため使いません。サイトのカテゴリは、あらかじめ用意した `Category` メタフィールドから選びます。未選択の場合のみ、旧「商品タイプ」を代用します。

### カテゴリの選び方

商品編集画面のメタフィールド「Category」から選びます。選択肢は技術担当者が事前に登録します。いま使える項目は次のとおりです。

| 選ぶ項目 | 一覧・パンクズの文言 | リンク |
| --- | --- | --- |
| テント・シェルター | テント・シェルター | `/products#tent-shelter` |
| テント・シェルター オプション | テント・シェルター オプション | `/products#tent-option` |
| タープ | タープ | `/products#tarp` |
| ペグ・ペグハンマー | ペグ・ペグハンマー | `/products#peg-hammer` |
| アクセサリー | アクセサリー | `/products#accessory` |

Category を選んで保存すると、次が自動で揃います。コードを追加する必要はありません。

- 商品一覧のカテゴリ分け
- 商品カードに出るカテゴリ名
- 商品詳細のパンクズ（「全ての商品 > （カテゴリ名）」）
- パンクズのリンク先（上表の `#...`）

先頭の「全ての商品」は常に `/products#all` です。Category 未選択のときは、詳細のパンクズは「全ての商品」だけになります。

新しいカテゴリが必要な場合は、登録担当者だけでは追加できません。このマニュアル末尾の「カテゴリを追加する」を技術担当者が行います。

## 手順2. URLハンドルを設定する

URLハンドルは、サイトのアドレス末尾です。  
例：ハンドルが `nokuta` → `https://（サイト）/products/nokuta`

1. 商品編集画面を下へスクロールする
2. 「検索エンジンでのリスティング」を探す
3. 鉛筆アイコン、または「ウェブサイトのSEOを編集する」をクリックする
4. 「URLハンドル」を半角英小文字とハイフンだけにする
5. 保存する

よい例：`moya500` / `nokuta` / `zig-stake20`  
避けてください：日本語、スペース、大文字混在

タイトルが英語なら、最初から正しいハンドルになっていることがあります。その場合は変更不要です。

公開後にハンドルを変えると、古いURLは開けなくなります。最初に確定してください。

---

## 手順3. ステータスと公開先を設定する

1. 商品編集画面の右側「ステータス」で「アクティブ」を選ぶ
2. 「販売チャネルとアプリ」または公開先の設定を開く
3. **Headless** にチェックを入れて公開する
4. 保存する

Headless に公開していない商品は、サイトから見えません。オンラインストアだけ公開しても、このサイトには出ません。

ファイルやメタオブジェクトも、使う場合は Headless へ公開してください。

---

## 手順4. バリエーション（カラー）を登録する

カラー展開がある商品は、バリエーションで登録します。

1. 商品編集画面の「バリエーション」へ進む
2. オプション名は `Color` または `カラー`
3. 値を追加する。MOYAシリーズの例：
   - Classic Yellow
   - Gold Beige
   - Shadow Gray
4. 保存する
5. 各バリエーションを開き、次を入力する

| 項目 | 例 | 説明 |
| --- | --- | --- |
| SKU | `CDS-M50SNCY` | 品番。空にしない |
| 価格 | `348620` | 税込の販売価格 |
| 比較価格 | 任意 | 販売価格より高い値を入れると SALE 表示 |
| 在庫 | 任意 | 販売する数量 |
| Color code | `cy` / `gb` / `sg` | サイト内部のカラーID。半角英小文字 |
| Swatch | カラーピッカーで色を選ぶ | カラー画像が無いときの色面 |

### Color code の目安

| カラー名 | Color code |
| --- | --- |
| Classic Yellow | `cy` |
| Gold Beige | `gb` |
| Shadow Gray | `sg` |
| その他 | 英小文字とハイフン（例：`black`） |

Color code と Swatch は、各バリエーション画面のメタフィールドにあります。商品全体のメタフィールドではありません。

カラーが1つだけの商品でも、SKU・価格・在庫はバリエーション側に入ります。デフォルトの1件を編集してください。

---

## 手順5. 画像・動画を登録する

### ファイルのアップロード

1. 左メニュー「コンテンツ」→「ファイル」
2. 「ファイルをアップロード」
3. 画像は WebP、長辺 2500〜3000px、品質 85% 程度
4. アップロードしたファイルを Headless へ公開する

サムネ用の別ファイルは不要です。サイトがギャラリー・カラーチップ・一覧に合わせて配信します。

ファイル名は内容が分かるものにしてください。例：`moya500-cy-gallery-01.webp`

### ギャラリーへの紐付け

ギャラリーは**バリエーションごと**に設定します。Classic Yellow と Gold Beige で写真が違う場合は、それぞれに別の一覧を付けます。

1. 商品編集画面で対象バリエーションを開く
2. メタフィールド「Gallery」を探す
3. 表示したい順にファイルを追加する
4. 保存する

順番がサイトのギャラリー順になります。動画も同じ一覧に入れられます。

ギャラリーが空の場合、サイトは次の順で代用します。

1. バリエーション画像
2. 商品メディア
3. プレースホルダー画像

### カラーチップについて

一覧や詳細のカラー選択ボタンは、次の優先順です。

1. そのカラーのギャラリー1枚目（画像）
2. 画像が無いときだけ Swatch の色

Swatch はメイン写真の代わりではありません。

---

## 手順6. 商品の表示設定を入れる

商品編集画面のメタフィールドで設定します。見つからない場合は、画面最下部のメタフィールド欄を開いてください。

### Member only（会員限定）

| 値 | 意味 |
| --- | --- |
| False | 一般販売。保存後に Flow が自動設定 |
| True | 会員だけ購入できる |
| 未設定 | 購入ボタンが使えません |

会員限定にするときだけ、保存後に `True` へ変更します。

### Is new（NEW表示）

| 値 | 意味 |
| --- | --- |
| True | 「NEW」を表示 |
| False / 未設定 | NEW を出さない |

新品番だけ `True` にしてください。SALE とは別です。

### Sales status（販売ステータス）

販売中・予約・終了などは、メタオブジェクト「Product sales status」で管理します。

1. 「コンテンツ」→「メタオブジェクト」
2. 「Product sales status」を開く
3. 「エントリーを追加」
4. 次を入力する
   - 表示名：`NOKUTA｜販売中` のように商品名を先頭に付ける
   - Product：対象商品を選ぶ
   - Status：下表のいずれか
   - Label：サイトに出したい文言（任意）
   - Color：ラベル色（任意）
5. Headless へ公開して保存する
6. 商品編集画面の `Sales status` に、今作ったエントリーを接続する

| Status | サイト上の意味 | 購入 |
| --- | --- | --- |
| `available` | 販売中 | できる |
| `comingSoon` | 近日発売 | できない |
| `waiting` | 入荷待ち | できない |
| `preorder` | 予約販売 | できる |
| `ending` | 在庫限り販売終了 | できる |
| `ended` | 販売終了 | できない |

Status は上の英単語をそのまま使います。日本語は Label に書いてください。

## 手順7. Feature を登録する

Feature は「商品の特徴カード」です。1カード = メタオブジェクト1件です。

### エントリーの作り方

1. 「コンテンツ」→「メタオブジェクト」
2. 「Product feature」を開く
3. 「エントリーを追加」
4. 次を入力する

| 項目 | 入れ方 |
| --- | --- |
| 表示名（Admin name） | 管理画面の一覧用。サイトには出ない。`商品名｜グループ｜タイトル` |
| Product | 対象商品 |
| Group | `Fabric` / `Flame` / `Structure` / `Parts` のいずれか |
| Title | カードの見出し |
| Body | 本文。改行可 |
| Media | 画像・動画。複数可。空ならグレー表示 |
| Link label / Link URL | 1本目のリンク（任意） |
| Link label 2 / Link URL 2 | 2本目（任意） |
| Link label 3 / Link URL 3 | 3本目（任意） |

5. Headless へ公開して保存する
6. 必要なカードの数だけ繰り返す
7. 商品編集画面の `Features` に、**サイトに出したい順**で追加する

### 表示名の例

```text
MOYA500｜Fabric｜軽量性と耐久性を両立するシルナイロン生地
MOYA500｜Flame｜DAC社製フレームを採用
NOKUTA｜Structure｜MOYA500との連結
```

Admin name は「どのカードか」を管理画面で見分ける名前です。サイトのリンク文言には使いません。グループ見出しは Group の値から自動でまとまります。大文字小文字の違いはサイト側で吸収しますが、入力は上の4語にしてください。

### リンクの入れ方（複数可）

同じ Feature 画面に、番号付きの欄を足します。1本目は今ある `link_label` / `link_url` です。2本目以降だけフィールドを追加します。`link_label_1` は作らないでください。

| 管理画面の名前（例） | キー | タイプ |
| --- | --- | --- |
| リンク文言 | `link_label` | 単一行テキスト（既存） |
| リンクURL | `link_url` | URL（既存） |
| リンク文言 2 | `link_label_2` | 単一行テキスト |
| リンクURL 2 | `link_url_2` | URL |
| リンク文言 3 | `link_label_3` | 単一行テキスト |
| リンクURL 3 | `link_url_3` | URL |

サイトに出る文字は「リンク文言」です。文言と URL が両方入っている組だけ表示します。片方だけだとその組は出ません。空の組は飛ばします。

ShopifyのURL欄はフルURLが必要です。

```text
https://candpluss.camp/products#tent-option
https://candpluss.camp/products/zig-stake20
https://candpluss.camp/products/aluminum-jammer-set
```

サイト側で `/products/...` のパスに変換します。関連商品がまだ無い場合は、商品登録後にURLを追加してください。4本目が必要なら `link_label_4` / `link_url_4` を同じルールで足せます（サイトは5本目まで読みます）。

## 手順8. Size & Spec を登録する

仕様表は2段階です。

1. 「Product spec group」で行を作る（材質、サイズ、重量など）
2. 「Product size spec」にまとめて商品へ接続する

### Spec group（行）

1. 「コンテンツ」→「メタオブジェクト」→「Product spec group」
2. 「エントリーを追加」
3. 次を入力する
   - 表示名：`NOKUTA｜材質`
   - Product：対象商品
   - Label：見出し（例：材質）
   - Value：内容。改行可
4. Headless へ公開して保存する
5. 行の数だけ繰り返す

### Size spec（まとめ）

1. 「Product size spec」で「エントリーを追加」
2. 次を入力する
   - 表示名：`NOKUTA｜Size & Spec`
   - Product：対象商品
   - Groups：今作った spec group を表示順に追加
   - Notes：注記（任意）
   - Drawing：図面画像（任意）
   - Downloads：取扱説明書など（任意）
3. Headless へ公開して保存する
4. 商品編集画面の `Size spec` に接続する

1商品につき Size spec は1件です。

---

## 手順9. 関連商品（任意）

オプション商品を詳細ページに出す場合だけ設定します。

1. 先に関連先の商品をShopifyへ登録する
2. 元の商品編集画面の `Option products` に、関連商品を追加する

関連先が未登録なら、空のままで問題ありません。

---

## 手順10. サイトで確認する

反映には最大約5分かかることがあります。開発環境では、保存後にブラウザを再読み込みしてください。

確認するページ：

- 一覧：`/products`
- 詳細：`/products/（URLハンドル）`

確認ポイント：

- タイトル、説明、価格、カラー
- カテゴリ名と、詳細ページのパンクズ
- NEW / 会員限定 / 販売ステータス
- ギャラリーの枚数と順番
- Feature のグループと本文
- Size & Spec
- ADD TO CART が意図どおり有効 / 無効

開発環境がある場合は、次でも確認できます。

```bash
npm run shopify:verify
```

## よくあるつまずき

| 現象 | 確認すること |
| --- | --- |
| サイトに商品が出ない | アクティブか。Headless に公開しているか。URLハンドルは半角か |
| Member only が空 | 保存済みか。保存後に再読み込みしたか。Flow は保存時に動く |
| 購入できない | Member only が未設定ではないか。Sales status が購入不可ではないか。在庫・販売可能か |
| カラーチップが色面だけ | そのバリエーションの Gallery 1枚目があるか |
| Feature がグループに入らない | Group が `Fabric` / `Flame` / `Structure` / `Parts` か |
| Feature のリンクが出ない | 同じ番号のリンク文言と URL が両方あるか。Admin name ではなく Link label に文言を入れているか |
| カテゴリがアクセサリーになる / パンクズが違う | メタフィールド Category を選んでいるか。未選択だと旧商品タイプを代用する。新しいカテゴリはサイト側の一覧定義も必要 |
| 途中の内容が一覧に出た | 同じハンドルの商品が Headless 公開されている。公開を外すか、内容を完成させる |

- [ ] 各バリエーションの Gallery を表示順で入れた

## 用語

| 言葉 | 意味 |
| --- | --- |
| ハンドル | URLの末尾。サイトの商品IDになる |
| バリエーション | カラーやサイズなど、買い分けの単位 |
| メタフィールド | 商品に追加する独自項目 |
| メタオブジェクト | Feature や仕様表、カテゴリなど、使い回すデータのまとまり |
| Category | サイトの商品カテゴリ。登録担当者は選択する。追加は技術担当者が行う |
| Headless | このサイトが商品情報を取得するための販売チャネル |
| Flow | 商品保存時に Member only を自動設定する仕組み |

## 初期設定（技術担当者）

登録担当者がカテゴリを選択できるように、先に次を用意します。1回だけ行います。

### 1. メタオブジェクト定義を作る

1. 「設定」→「メタフィールドとメタオブジェクト」
2. 「メタオブジェクト」の「定義を追加」
   - メタフィールド定義の「商品」ではない
3. 次を設定する
   - 名前：`Product category`
   - タイプ：`product_category`
4. フィールドを追加する

| フィールドラベル | キー | タイプ | 内容 |
| --- | --- | --- | --- |
| Admin name | `admin_name` | 単一行テキスト | 管理画面の表示名 |
| Slug | `slug` | 単一行テキスト | サイト内部ID。半角英小文字とハイフン |
| Label | `label` | 単一行テキスト | サイトに出す日本語名 |

5. Storefront APIアクセス：ON
6. 保存する

### 2. カテゴリエントリーを作る

「コンテンツ」→「メタオブジェクト」→「Product category」で、次を作成し、Headless へ公開します。初期の5件は作成済みです。

| Admin name / Label | Slug |
| --- | --- |
| テント・シェルター | `tent-shelter` |
| テント・シェルター オプション | `tent-option` |
| タープ | `tarp` |
| ペグ・ペグハンマー | `peg-hammer` |
| アクセサリー | `accessory` |

Slug は半角英小文字とハイフンだけにしてください。増やしたい場合は「4. カテゴリを追加する」へ進みます。

### 3. 商品メタフィールドを作る

1. 「設定」→「メタフィールドとメタオブジェクト」→「商品」
2. 「定義を追加」
3. 次を設定する
   - 名前：`Category`
   - ネームスペースとキー：`custom.category`
   - タイプ：メタオブジェクト → `Product category` を参照
   - 値：1つ
   - Storefront APIアクセス：ON
   - 定義をピン留め：ON
4. 保存する

これ以降、商品編集画面のメタフィールド「Category」から、上記の項目を選べます。Shopify標準の「商品タイプ」は自由入力のまま残りますが、サイト表示には使いません。

既存商品（MOYA500、NOKUTA など）にも、同じ Category を選んで保存してください。未選択の間は、従来の商品タイプを代用します。

### 4. カテゴリを追加する

一覧タブ・パンクズ・商品の選択肢を増やすときは、Shopify だけでなくサイトのカテゴリ定義も更新します。どちらか一方だけでは、文言とリンクがずれます。

1. 「コンテンツ」→「メタオブジェクト」→「Product category」
2. 「エントリーを追加」
3. 次を入力する
   - Admin name / Label：サイトに出す日本語名（例：`チェア`）
   - Slug：半角英小文字とハイフンのみ（例：`chair`）
4. Headless へ公開して保存する
5. サイトの `types/product.ts` の `productCategories` に、同じ label と slug を追加する
6. 必要なら `lib/shopify/products.ts` のカテゴリ判定（旧商品タイプの代用）も更新する
7. 商品の `Category` から、新しい項目を選んで保存する

Slug を後から変えると、古い `/products#旧slug` のリンクは開きません。公開後は Label の変更だけにしてください。

既存カテゴリの表示名だけ変える場合は、次の3箇所を同じ文言にします。

- Product category エントリーの Admin name と Label
- `types/product.ts` の `productCategories` の label
- 手順書のカテゴリ表

### 5. Feature の複数リンクを使えるようにする

1回だけ行います。すでに Product feature 定義がある前提です。新しいメタオブジェクトは作りません。

1. Product feature 定義を開く
2. 既存の `link_label` / `link_url` はそのまま残す
3. 「フィールドを追加」で次を足す。名前は日本語、キーは半角にする

| 名前 | キー | タイプ | 値 |
| --- | --- | --- | --- |
| リンク文言 2 | `link_label_2` | 単一行テキスト | 1つ |
| リンクURL 2 | `link_url_2` | URL | 1つ |
| リンク文言 3 | `link_label_3` | 単一行テキスト | 1つ |
| リンクURL 3 | `link_url_3` | URL | 1つ |

4. 各フィールドの Storefront APIアクセスを ON にする
5. 保存する

Admin name は触らないでください。あれは Feature カード全体の管理画面用の名前です。
